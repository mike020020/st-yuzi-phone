# 1 - 建项导表与全表盘点

本阶段负责在收到有效表格后立即建项、拆成可编辑 Markdown、生成初始表格产物并盘点全部表，不提前设计或批量生成页面。

本阶段要主动带用户认识产物。说明 `tables/source/*.md` 时先称为“每张表各自的可编辑说明文件”，再补充它是 Markdown；说明 generated JSON 时先称为“由这些说明文件自动合成、最终可交付的表格文件”。

## 前置阅读

读取 `AGENTS.md`、`docs/bundle/source-project-format.md`、`docs/tables/README.md`、`docs/tables/markdown-source-format.md`，以及 workflow 中 setup 阶段的全部 `requiredReads`。

## 输入合同

- 用户提供的完整 chatSheets JSON 或可读取路径。
- 可选的项目 ID 和显示名称；用户未指定时，AI 必须从输入文件名和目标自动派生，不得因此延迟拆分。

正式导入只接受 `mate.type === "chatSheets"` 且至少含一张 `sheet_*` 表的完整模板。历史兼容形状、单张表片段和从页面猜出的字段不能冒充正式输入。有效输入已经提供时必须立即进入 dry-run、建项和拆分，不得停在只读检查等待用户说明拆表方式；缺少真实输入时才可以先创建空白草稿并停在导入前。

## 执行顺序

1. 从用户指定信息或输入文件名自动确定项目 ID 和显示名，先用 `--dry-run` 核对目标路径，再创建项目：

   ```powershell
   npm run project:new -- --projects-dir <projects-dir> --id <project-id> --name <project-name> --dry-run
   npm run project:new -- --projects-dir <projects-dir> --id <project-id> --name <project-name>
   ```

2. 导入前只读检查输入；确认目标项目尚未导入，随后立即正式导入并拆分，不额外询问用户怎样拆：

   ```powershell
   npm run project:import-tables -- --project <project.json> --input <chatSheets.json> --dry-run
   npm run project:import-tables -- --project <project.json> --input <chatSheets.json>
   ```

3. 核对项目内三件套：

   - `tables/original/imported.json` 是未修改的原始字节副本；
   - `tables/source/*.md` 是逐表人工事实源；
   - `tables/generated/tables.json` 是由 Markdown 重建的完整 chatSheets。

4. 运行表格往返和草稿检查，再读取机器状态：

   ```powershell
   npm run tables:cli -- roundtrip <chatSheets.json>
   npm run project:check -- --project <project.json>
   npm run project:status -- --project <project.json> --json
   ```

5. 向用户展示全部表盘点：每张表的 `sheetKey`、表名、表头、初始状态、当前表和对应 Markdown 路径。导入后的队列必须覆盖全部表，保持导入顺序；不得因用户最先提到某页、页面相似或工作量较大而自动删减、合并或跳过。
6. 拆分完成后只询问下一步方向：
   - 直接开始美化，并确认当前表的具体美化目标；
   - 先选择要讨论的表或美化方向，但不从全表队列删除其他表；
   - 先修改 `tables/source/*.md`，可以由用户直接手改，也可以由 AI 按确认后的结构调整。
7. Markdown 修改完成后由 AI 执行 `tables:cli build`、`project:status --refresh` 和草稿检查，展示重新合成的 `tables/generated/tables.json`。被明确删除的 Markdown 表会直接退出 generated 和制作队列，不需要再标记跳过；不得让用户手工维护 generated JSON。
8. 每次拆分、检查或重建后都给出下一步建议和理由，但不替用户决定是先改表还是开始美化。用户已明确选择某条路径时，直接沿该路径继续，不重复询问。

## 本阶段产物

- 可为空起步、导表后具备真实 `tablesFile` 的源码项目；
- 原始 JSON、逐表可编辑 Markdown、初始或修改后重新合成的 generated JSON；
- `workflow-state.json` 中默认覆盖全部表的制作队列；
- 一份给用户确认的全表盘点。

确认三件套和队列无误后，只把第一张 pending 表设为当前工作对象，进入 `2-逐表需求与字段合同.md`。不要在本阶段为多张表预建 item。
