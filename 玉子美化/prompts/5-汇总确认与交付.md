# 5 - 汇总确认与交付

本阶段只在队列中每张表均为 `completed` 或 `skipped` 后执行。先汇总、再等待用户确认；确认之前不得做发布检查、打包或回读。

汇总先用大白话回答三个问题：做完了什么、哪些没做或没模拟、确认后会生成什么。技术名词、命令和哈希放在结果说明之后。AI 要明确建议是否适合进入发布，并说明仍有的风险，但最终确认必须由用户作出。

## 生成最终汇总

运行只读状态命令：

```powershell
npm run project:status -- --project <project.json> --json
```

向用户逐项展示：

- 完成表及其唯一 item、字段合同；
- 跳过表、用户给出的原因；
- 制作期模拟为 `not-run`、`skipped` 或 `failed` 的表及说明；
- 已通过模拟的表；
- 表结构修改及其失效/重做记录；
- 三份预期交付路径和真实宿主待验收边界。

这必须是“完成、跳过和未模拟”的完整汇总，不能只报成功项。若仍有 pending/invalidated 表、非跳过表没有唯一 item、字段与当前 generated JSON 不符，返回逐表阶段。

## 用户确认门禁

请用户明确确认当前汇总，并先给出下一步建议、理由及确认后的实际影响。用户提出修改时回到对应表；用户未确认时停止，不得自行写入确认。确认只绑定当前摘要哈希，队列、字段、表结构或模拟记录变化后必须重新汇总。

获得确认后，严格按以下顺序执行：

```powershell
npm run project:status -- --project <project.json> --confirm
npm run project:check -- --project <project.json> --release
node tools/pack-preset.mjs <project.json> <bundle.json>
node tools/readback-preset.mjs <project.json> <bundle.json>
```

任一步失败都停止交付正式 Bundle，保留证据并修复后从失效的门禁重跑。目标 Bundle 已存在时默认拒绝覆盖；只有用户明确允许覆盖，才使用工具支持的覆盖参数。

## 三份独立交付

1. 表格 JSON：项目内 `tables/generated/tables.json`；
2. 美化 Bundle：打包并回读一致的 `output/*.json`；
3. 可编辑源码：含 `project.json`、`workflow-state.json`、Markdown、页面和资源的项目目录。

分别给出实际路径、哈希/回读结果和已运行命令。Bundle 不创建、修改、写入、迁移或安装数据库表，也不代替表格 JSON。

最终报告把自动检查、制作期模拟和真实宿主验收分开。没有真实 SillyTavern 证据时，Blob ESM、CSP、路由、数据库、IndexedDB、主题叠加、滚动恢复、资源 Blob URL 和页面生命周期必须标为待人工验收。
