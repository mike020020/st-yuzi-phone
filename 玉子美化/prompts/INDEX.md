# prompts 索引

`data/workflow-index.json` 是机器可读流程合同；本目录把同一合同拆成适合 AI 与用户逐步协作的阶段提示。先读 `0-总览与启动.md`，再严格按机器状态推进。

| 文件 | 作用 | 离开条件 |
| --- | --- | --- |
| `0-总览与启动.md` | 判断新建、继续或只读任务，核对独立边界与环境 | 找到真实项目阶段或必要输入 |
| `1-建项导表与全表盘点.md` | 创建空草稿、导入完整 chatSheets、建立全部表队列 | 三件套等价且已展示全表盘点 |
| `2-逐表需求与字段合同.md` | 对当前表分组访谈需求、字段映射、跳过或改表决定，并持续记录 | 用户确认当前表需求与字段合同，或明确跳过 |
| `3-逐表设计与实现.md` | 参照小手机变量设计当前表，获得明确开工许可后实现并登记唯一 item | 当前表源码与草稿静态检查通过 |
| `4-单表检查与模拟.md` | 每表询问制作期模拟并记录真实状态 | 用户确认当前表结果 |
| `5-汇总确认与交付.md` | 汇总后等待确认，再发布检查、打包、回读 | 三份独立产物交付且边界如实报告 |
| `制作提示.md` | 逐表制作、Runtime、源码与安全硬约束 | 全程适用 |

阶段二的 2 → 3 → 4 会为每张未跳过表重复执行。一次只处理当前表；需求和设计每轮集中询问一组相关决定并逐项给出建议，回答持续写入当前表访谈记录，设计完成后还要取得明确开工许可，不得批量越过需求确认、设计确认、模拟选择或结果确认。

`npm run verify`、草稿检查和本地 preview 都不能冒充真实 SillyTavern 验证。真实宿主验收始终单独记录。
