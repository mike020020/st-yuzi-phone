# 3 - 逐表设计与实现

本阶段把已经确认的当前表需求和字段合同转成一套独立、可编辑的页面源码。只实现当前表，不进入下一张表，也不提前打包最终 Bundle。

展示设计时先描述用户实际会看到的页面、阅读顺序和操作方式，再补充实现细节。AI 应推荐一个最合适的设计方向并说明原因，也要如实指出取舍；视觉风格和重要交互仍由用户确认，不能因为 AI 已经有方案就直接动手。

## 设计确认

读取 `docs/runtime/runtime-api-v1.md`、作者类型声明、源码工程格式、`docs/phone-ui-variables.md` 和 `prompts/制作提示.md`。五页源码参考只能提供视觉结构、字段解析和本地交互思路，不能复制宿主耦合或假设字段完全相同。

如果用户在本表需求中明确要求酒馆、SillyTavern、TavernHelper 或酒馆输入框能力，再按需读取 `docs/architecture-notes.md` 和 `docs/sillytavern-api.txt`；普通表格美化不读取这两份资料。用户明确要求宿主 DOM 时，可以把指定选择器作为当前 item 的宿主依赖实现，并在设计中写清找不到元素、页面尚未加载和宿主改版时的降级行为。

`docs/phone-ui-variables.md` 是标题栏尺寸、控制热区、图标形状和全局视觉一致性的权威参照。玉子美化仍是独立项目：不得导入文档所指向的小手机共享 CSS、JavaScript 或父项目资源；实际需要的样式变量、图标和资源必须作为当前项目源码或已登记 Bundle 资源实现。

先向用户提交当前表设计稿，至少包含：

- 页面根作用域 class 与主要区块层级；
- 每个区块使用的真实字段和解析方式；
- 初始、加载后、空数据、坏数据、长内容和窄屏状态；
- 本地交互及允许使用的 Runtime action；
- `getState()` 首次渲染、`subscribe()` 更新、Abort 和 disposer 清理方案；
- 可访问性和降级行为。

提交设计后继续用一组相关问题解决尚未确定的视觉和交互取舍，每轮把双方原话按顺序追加到 `notes/interview-<sheetKey>.md`，并在最后展示完整设计摘要。随后明确询问：“你还有没有想补充或修改的地方？如果没有，我就按这个方案开始制作。”只有用户明确表示没有补充并同意开始制作，才可编辑源码；这项授权以访谈中的用户原话为准，不另写推断状态。“大概可以”“先看看”或此前提供草图不视为开工授权。若设计引出表结构变化，返回上一阶段的改表确认分支。

## 实现合同

1. 页面默认只创建一个 `mount.js`，把 HTML、CSS、SVG 和交互集中在其中；确有拆分必要或用户明确要求时才增加其他页面文件。所有源码都放在当前项目目录内，CSS 选择器收窄到本页唯一根 class。
2. 整页根容器必须撑满 `context.root` 的可用区域。使用 Flex 或 Grid 时，根据用户确认的设计显式写明主布局方向或轨道，不依赖 `display:flex` 默认横向；内容区必须得到真实可用宽高，不能被其他区块挤成窄条或空白区。
3. mount 显式导出 `export function mount(context)` 或 async 形式，只操作 `context.root`。
4. 状态来自 `context.getState()` / `context.subscribe()`；事件、定时器、订阅和观察器必须由幂等 disposer 清理，并响应 `context.signal`。
5. 动态资源只用 `context.resolveAsset()`；导航只用四个 `context.actions`，并处理非 `ok` 结果和按钮复位。
6. 不读取数据库、不跨表、不调用 AI、世界书、手机内部对象或 `AutoCardUpdaterAPI`；只有用户明确要求时，才访问已经记录在设计中的宿主 DOM 或酒馆外部能力。
7. 只编辑 source/project；不直接编辑最终 Bundle 或原始导入 JSON。

## 一次制作收尾

用户同意开工后，连续完成页面源码、语法与路径核对、当前表唯一 item 登记和一次草稿静态检查。这些是一次制作内部动作，不逐项停顿或向用户播报；只有失败、需要覆盖或出现新的决定点时才说明。每个实际依赖字段重复传入 `--field`；初次登记的模拟状态通常是 `not-run`：

```powershell
npm run project:add-item -- --project <project.json> --table <sheet-key> --id <item-id> --name <item-name> --mount <mount.js> --field <field-name> --preview-status not-run
```

确有拆分时再传入对应页面文件参数。登记路径必须进入 `project.json`，`target.tableName` 与字段必须匹配当前 generated JSON。常规 item 登记和后续状态记录不重复 dry-run。

登记后运行草稿静态检查：

```powershell
npm run project:check -- --project <project.json>
```

普通页面只运行这一次当前项目草稿检查，不运行全仓 `npm run verify`。检查失败时留在当前表修复并重跑；不得把失败记录成完成。静态检查通过后，用大白话告诉用户页面已制作完成并进入 `4-单表检查与模拟.md`，仍不进入下一张表。
