# 领域文档

工程类 Skill 在查看或修改代码前，应按本文件约定读取项目的领域知识与架构决策。

## 开始查看代码前

- 如果根目录存在 `CONTEXT.md`，先读取其中与当前任务相关的领域术语和业务规则。
- 如果 `docs/adr/` 中存在与当前模块相关的 ADR，先阅读这些架构决策记录。
- 如果上述文件或目录尚不存在，直接继续工作，不提示缺失，也不为了补齐形式而提前创建空文件。
- `/domain-modeling`、`/grill-with-docs` 或 `/improve-codebase-architecture` 会在真正形成术语或重要决策时按需创建这些文件。

## 文件布局

本项目采用单一领域上下文：

```text
/
|-- CONTEXT.md
|-- docs/adr/
|-- modules/
|-- scripts/
`-- index.js
```

`CONTEXT.md` 用来记录项目的标准术语、概念关系和业务规则；`docs/adr/` 用来记录重要、难以撤销且存在真实取舍的架构决策。

## 使用统一术语

在 Issue 标题、重构方案、调试假设、测试名称和代码命名中，使用 `CONTEXT.md` 已定义的标准术语，不随意换成近义词。

如果需要的概念尚未写入词典，先判断它是否真是项目领域概念；如果确实存在知识缺口，将它留给 `/domain-modeling` 补充。

## 发现 ADR 冲突时

如果准备进行的工作与已有 ADR 矛盾，必须明确指出冲突及重新讨论的理由，不能静默覆盖原有决定。
