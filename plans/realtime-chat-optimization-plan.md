# QQ 重构方案 v1.1（已确认实施基线）

> **已归档：**本文已被 `.scratch/qq-v2/spec.md` 的 QQ v2 规格完整取代，不再具有需求或实施权威，也不作为待完成事项来源。

这份文档只保留早期 QQ 重构讨论的历史背景。当前及后续需求全部以 QQ v2 规格为准。

## 1. 一句话目标

QQ 是小手机里的独立系统 App。它自己保存联系人、会话、消息、媒体、提示词和 API 预设；它不属于任何表格，也不把聊天内容当成表格的一种显示方式。

## 2. 已确认的硬边界

1. 不迁移、不兼容旧聊天数据，也不识别旧聊天表为任何小剧场入口。
2. 删除旧聊天专属 viewer、运行时、设置页、样式和表源；广场、论坛等现有 Theater 场景继续保留。
3. QQ 不读取数据库插件的 API 当前配置，也不复用数据库 API 预设。
4. QQ 不使用“先判断要不要主动发消息”的额外 AI 步骤。正文每达到设定轮数，就直接发起一次 QQ AI 请求。
5. QQ 世界书必须是真实世界书条目，不能只在一次 QQ 请求里临时拼 prompt。
6. 世界书内容不做 token 预算、摘要、截断或静默筛选。用户选择的内容按原文写入。

## 3. 路由和界面

QQ 是 Home 上的系统 App，使用独立 route：

- `qq`：会话列表。
- `qq:contacts`：联系人。
- `qq:settings`：QQ 设置。
- `qq:chat:<conversationId>`：单个会话。

QQ 聊天页保留真实 QQ 风格的标题栏左右按钮。右上角进入 QQ 设置；QQ 设置只负责选择 API/指令预设和调整聊天运行参数，预设的创建与编辑统一放在小手机设置。聊天页应具备会话列表、联系人、聊天气泡、输入区、媒体工具和消息选择入口，视觉上优先参考现实 QQ，而不是表格页面。

## 4. QQ 自己的数据怎么保存

QQ 用户数据保存在独立 IndexedDB 数据库 `yuzi-phone-qq`，按当前酒馆聊天 scope 隔离。它保存：

- 联系人与会话。
- 全量消息和故事时间。
- 图片、视频、语音、表情和转账等消息元数据。
- API 预设、提示词、QQ 设置和世界书关联。
- 单独手选进入世界书的消息状态。

这解决了“聊天记录要保留，但不一定都注入世界书”的问题。世界书只是 QQ 数据的一种投影，不是 QQ 的事实来源。

第一版不做聊天记录导入导出、备份恢复或 reroll。以后做这些功能时，直接以 QQ IndexedDB 为来源，不重新接回任何表格。

## 5. 独立 API 预设

小手机设置中的“API 与世界书”工作台负责管理 QQ 独立 API 预设。每条预设只需要：

- 名称。
- API 地址。
- 密钥。
- 模型。
- 温度。
- 最大输出。

密钥使用 WebCrypto 加密保存。预设列表和设置页只能显示“已保存/未填写”，不能把密钥明文回填到页面或普通读取结果中；只有实际发请求时才取得可用配置。

不提供数据库当前配置选项，不需要测试按钮，也不加入超时、填表预设或剧情推进预设等旧设置。API 与 AI 指令预设在小手机设置中创建、编辑、删除；QQ 设置只选择所用的 API 预设、聊天指令预设和主动消息指令预设。正文上下文轮数与 QQ 会话历史条数仍在 QQ 设置中，轮数或条数设为 `0` 表示全部。

## 6. 手动聊天和协议

用户发送后，QQ 把消息写入自己的仓库，再用所选独立 API 请求回复。QQ 请求由三部分组成：

1. 用户配置的聊天提示词。
2. 当前正文上下文与正文实际启用的世界书提示词部分。
3. 当前 QQ 会话历史。

QQ 不再扫描并全量塞入所有世界书条目。它应尽量与酒馆正文当前拿到的世界书内容一致；QQ 聊天本身的历史则通过真实世界书条目让正文和其他插件共同看见。

AI 回复用受校验的 QQ 消息协议解析。基础文本外，还要能表达图片、视频、语音、表情和转账。界面必须正确展示这些类型；用户端图片上传、表情、语音和转账入口接入前不得伪造“已经发送成功”的假消息。

## 7. 世界书注入

每个开启注入的 QQ 会话对应一条由 QQ 拥有的真实世界书条目。

- 默认蓝灯；绿灯可填写关键词。
- 用户可设置注入深度，默认 `999`。
- 用户可选择注入角色。
- 时间范围按故事时间计算，可选一小时、一天、一个月、一年或全部。
- 只读取全局数据表里的当前故事时间字段，不使用浏览器现实时间。
- 时间范围内的消息原文全部写入，不做预算和压缩。
- 用户可以单独手选一段消息注入；手选消息应按原文保留，即使它不在当前时间范围内。
- 关闭会话注入时，立即删除这条会话拥有的世界书条目。QQ 会话和本地消息仍保留，重新开启时重新生成和同步条目。

这样正文、剧情推进和其他读取世界书的插件看到的是同一份 QQ 内容，而不是只有 QQ AI 知道的临时上下文。

## 8. 主动消息

主动消息是一个明确的计数器，不是概率检查：

1. 用户在 QQ 设置中开启或关闭它。
2. 用户填写“正文每经过 N 轮”。
3. 正文每累积到 N 轮，固定触发一次 QQ AI 请求。
4. 该请求使用单独的主动触发提示词，并由 QQ 协议直接产出要发送的消息。

第一版不引入 `phone_event` 数据，也不额外调用 AI 询问“这次是否应该发”。计数、scope 切换和重复事件都要防止同一轮重复触发。

## 9. 设置归属

小手机总设置页保留通用系统设置，并提供两个全局管理入口：“API 与世界书”负责 QQ 独立 API 预设及现有世界书工作台，“AI 指令预设”负责聊天回复与主动消息的分段提示词。旧聊天链的字符数、超时、填表预设和剧情推进预设选择全部移除。

QQ 设置包含：API 预设选择、聊天指令预设选择、主动消息指令预设选择、正文上下文轮数、QQ 历史条数、主动消息开关与轮数，以及完整的世界书注入参数。QQ 设置不提供预设正文或 API 密钥编辑器。

## 10. 这版明确不做

- 旧聊天数据迁移。
- 旧聊天表兼容。
- 数据库当前 API 配置适配。
- reroll。
- 聊天记录导入、导出、备份和恢复。
- `phone_event` 数据模型。
- 为了控制 token 而私自删减用户选中的 QQ 原文。

## 11. 验收清单

实施完成后至少验证：

1. Home 能打开 QQ，QQ 不经过任意表格 route。
2. 新建 API 预设后，普通读取不能得到明文密钥；实际请求可使用它。
3. 手动消息、图片、语音、表情和转账的存储、协议解析和渲染边界明确，不会伪装成功。
4. 每个开启注入的会话只有一条 QQ 自己拥有的世界书条目；关闭后这条目被删除。
5. 故事时间窗口和手选消息按原文同步，无隐式 token 上限。
6. 正文达到 N 轮时恰好触发一次主动 QQ 请求，不先走“是否发送”判断。
7. 广场/论坛 Theater 仍正常运行，QQ 不重新变成其中一种表格或小剧场。
8. `npm.cmd run check`、`npm.cmd run lint`、`npm.cmd run build` 与 `git diff --check` 全部通过。
